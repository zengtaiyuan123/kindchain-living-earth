# KindChain 独立邮箱登录上线步骤（v172）

当前交付为经过测试的源码补丁，不是已经运行的邮箱登录网站。保留原站点直到独立站验收通过。

## Simon 需要提供的授权

1. 连接已有 Supabase 项目；没有项目时由项目所有者建立并授权。无需逐个接 Gmail、Hotmail，它们只是用户收验证码的邮箱。
2. 授权现有独立 Cloudflare 部署账户及拟使用域名的 DNS 管理。已有 Zhipeng 环境可复用，但需先核实资源归属和备份。不要把密码或 API secret 发在聊天里。
3. 提供可配置的生产邮件服务与发件域名授权。默认 Supabase 发信仅限项目团队授权邮箱，不能作为公开注册的邮件服务。

## 执行顺序

- 导出 v172 源码，应用本补丁；不在原 Sites 项目中替换平台认证。
- 配置 Supabase Email OTP，允许新用户注册。邮件模板显示 `{{ .Token }}`，可使用随包的 email-template.html；模板主题为“KindChain 登录验证码 / Your sign-in code”。配置有效期和频率限制，代码支持 6–10 位数字。
- 接入生产 SMTP，验证发件域名 DNS；检查注册和验证端点的服务端限流。验证码挑战若启用必须配套 UI/请求字段，不可只打开上游开关。
- 建立独立 Worker、D1、R2、Images；运行时设置 SUPABASE_URL、SUPABASE_PUBLISHABLE_KEY、AUTH_ORIGIN。仅使用 publishable 或旧 anon key。密钥通过平台秘密配置注入。
- 按 README 构建并部署。原用户数据需要备份与显式身份映射；不能仅凭相同邮箱自动合并账户。代码导出不包含线上 D1/R2 数据。
- Gmail 和 Hotmail 两个真实账户测试收码、注册、错误/过期码、退出、过期重登、互相发信与回复、跨账户私有数据拒绝访问。手机测试键盘、填码、慢网及草稿。
- 验收通过后再切换正式域名。当前会话最长一小时，到期需重新收码；尚无自动续期或 Google/Microsoft 一键 OAuth。

## 其他功能如何完成

| 功能 | 外部条件 | 接通后必须验收 |
|---|---|---|
| 支付 | Stripe 商户账户、匹配模式的 API key 和 webhook secret | 测试付款、重复回调、金额/币种、退款、争议；然后评估真实收款启用 |
| 提现 | Stripe Connect、创作者实名和收款资料、平台结算规则 | 可结算余额、退款冻结、转账重试、防重复、Connect 余额到银行的出款状态 |
| 大屏 | 一个真实运营商的屏幕/时段库存、报价、预订和播出回执接口或人工履约协议 | 一笔从订单到播出证据的完整试单及失败退款；在此之前不卖已保证的大屏投放 |

支付与提现的代码入口已存在，但尚未与真实商户环境联调。大屏仍需业务供应方，不能仅靠代码宣布接通。
